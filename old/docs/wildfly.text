
* To run Wildfly at localhost port 8080
* Just run the ./standalone.sh
* Admin console will be http://localhost:9990/console

* To run the server at diffrent port

* ./standalone.sh -Djboss.socket.binding.port-offset=1000
* The new port will be  8080 + 1000 = 9080
* Admin console will be http://localhost:10990/console
* i.e 9990 + 1000 = 10990


* Binding public interface to different ip(s), default is 127.0.0.1
* ./standalone.sh -b=192.168.1.1 


*  bind to all available IP addresses, then you can do:
* ./standalone.sh -b=0.0.0.0

* WildFly “management” interface can be bound to a specific IP address as:
* ./standalone.sh -bmanagement=192.168.1.14

* Or, bind “management” interface to all available IP addresses as:
* ./standalone.sh -bmanagement=0.0.0.0

* Of course, you can bind WildFly “public” and “management” interface    together as:
* ./standalone.sh -b=0.0.0.0 -bmanagement=0.0.0.0

* Domain Mode
*All the servers managed by Domain are known as members of domain. 
*All the members of domain can share same configuration/deployments. 
*In Domain mode we can create a server group and then can add number of servers to that group. 
*With this whatever we do on this Server Group, everything will get replicated to each server in Server Groups.

* Start wildfly in domain mode

* ./domain.sh

*Notice the difference between the number of services that got started:

1) In Standalone (183 out 0f 232)  And

2) Domain mode (207 out of 255)

*In general you have two options to setup SSL/HTTPS support for your server:

1) Using the pure Java implementation supplied by JSSE
2) The native implementation based on OpenSSL

*In both cases you have to configure keys and (self-signed) certificates for your web server. 


 # Pure Java SSL-Setup using keytool
 * We will generate a secret key/certificate and store it in a file called a "key store". 

 *The certificate is valid for 30 years = 10950 days. 
 *The password use for encryption is "secret".

 *One important issue is the common name (CN) of the certificate. 
 *For some reason this is referred to as "first and last name". 
 *It should however match the name of the web server, or some browsers like IE will claim the certificate to be invalid although you may have accepted it already.
